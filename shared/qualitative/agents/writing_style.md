# 写作风格要求（所有 Agent 共享）

> 强周期或重资产公司“至少 5 个可渲染图表”，且每个图表必须显式声明 `chart_ready`；严格字段以 `shared/report_contract.json` 为准。

1. **结论先行**：每个维度开头用 **一句话加粗结论** 引导读者，分析论证放在后面
2. **重点突出**：关键数据和评级用 **加粗** 标识，不要让关键信息淹没在大段文字中
3. **格式选择**：结构化对比数据用表格，分析论述用段落，不要把所有内容都堆进表格
4. **逻辑过渡**：段落之间有清晰的因果/递进关系，避免信息跳跃
5. **去重**：维度之间不重复引用同一数据或结论，交叉引用时简短提及即可
6. **通俗表达**：用通俗语言解释行业术语和专业判断，让非专业投资者也能理解核心逻辑
7. **金额单位**：金额单位优先使用亿元或万元，不要在正式报告正文中使用百万元；若输入数据为百万元口径，先换算为亿元或万元后呈现
- **利润口径**：使用 GAAP 归母净利润（除非 preflight 指定其他口径）

## 样板化成品感要求

8. **自适应研究计划**：正式报告必须使用独立二级标题“## 自适应研究计划”，先识别公司类型、核心质量问题和关键因果链，再按公司逻辑选择证据；必须包含表头 `| 项目 | 判断 | 证据路径 | 反证重点 |`；证据必须服务核心判断，不得机械照搬样板公司的细分分项，不同公司可以使用不同证据路径。
9. **核心商业质量问题**：全文必须围绕一个核心商业质量问题展开，每个维度都要回扣这个问题；D1：这个模式如何赚钱，D2：为什么能获得超额回报，D3：外部变量会不会破坏质量，D4：管理层如何配置这份现金，D5：管理层叙事是否解释边际变化，D6：结构是否影响主业质量，交叉验证：这些证据是否互相支持。
10. **样板级研究层**：报告必须使用独立二级标题“## 交叉验证与深度分析”，并包含交叉验证、数字与叙事的匹配、核心矛盾、被忽视信号、非经营项、口径差异、触发比例计算；必须逐字覆盖研究层：数字与叙事的匹配、核心矛盾、被忽视信号、非经营项、口径差异；交叉验证必须输出综合复判，说明当前评级为什么仍成立或为什么需要下调；交叉验证必须输出评级复判表，覆盖支持当前评级的证据、削弱当前评级的证据、证据冲突的解释、评级动作：维持 / 下调 / 上调 / 观察、触发重评的最小变量；深度总结必须明确当前评级为什么仍成立或为什么需要调整，不得只重复 D1-D6 小结；这些内容用于提升研究深度，不是固定复制某一家公司的分项。

8. **首屏闭环**：报告开头必须同时呈现公司本质、核心优势、最大风险、反证条件，避免只报喜或只堆事实。
9. **章节节奏**：每个大维度按“本节判断 → 支撑证据 → 反向证据/限制条件 → 交叉验证 → 本章小结”组织；不要只写正面证据。
10. **表格服务判断**：表格用于业务拆分、趋势、对比和风险检查；每张表前必须用读者化结论句说明它支持的判断，表后必须用一句话解释其投资含义。不得把结构说明照抄成正文，正文不要出现“这张表回答 / 下表回答 / 用于回答 / 避免只证明 / 不检查伪优势 / 不要只写优势”等模型指令句。
11. **维度正文节奏**：D1-D6 每个维度必须按“判断句 → 证据模块 → 投资含义 → 本章小结”组织；每个维度第一段必须先给出本章判断，让 HTML 读者能先看到结论再看证据；证据模块不得连续堆叠超过两张表，中间必须用段落解释证据如何影响评级、风险或反证阈值；每个核心表格后必须回扣核心商业质量问题；本章小结必须压缩为本章结论、最重要证据、观察风险 / 重评触发；不得把维度写成数据表连续堆叠。
11. **事实/推论/判断分离**：先说明事实，再解释含义，最后给出判断；不要把年报原话直接当结论。
12. **伪优势过滤**：遇到高 ROE、高毛利、品牌叙事、政策补贴、管理层口号时，必须判断它是真优势、半真优势还是伪优势。
13. **样板证据模块**：正式 qualitative 报告必须包含收入质量拆分、利润桥、量价成本拆解、现金转化、治理红旗、MD&A 叙事 vs 财务证据、伪优势过滤、未来观察变量；这些模块服务判断，不为了堆数据。
14. **源报告生成优先**：微信公众号可读性和成品感必须在源报告生成时完成，不得依赖微信后处理补核心分析内容；后处理只做排版、图表插入和读者化清理。
15. **公司类型化证据模块**：每个维度至少一组公司专属证据，必须包含公司专属数字、业务事实或同业对比，不得只写通用框架语；轻资产公司写业务线拆分、费用率 / 渠道库存、研发、海外区域、平台生态；轻资产科技硬件、企业协作终端、企业通信终端和全球化办公硬件公司写产品结构、研发效率、渠道库存、平台生态、兼容认证、海外区域暴露、现金转化、技术迭代风险，不强制套用吨经济或强周期价格成本链；强周期公司写单位经济模型、量价成本拆解、周期位置、外部变量、销量 / 吨价 / 吨成本 / 吨毛利；重资产公司写 Capex/D&A、固定资产占比、折旧压力、维护性投入和 FCF 约束。强周期或重资产公司必须生成公司类型化证据模块，至少连接产业坐标、区域/客户结构、同业/区域坐标、单位经济模型、利润桥、现金质量和反证阈值。
16. **样板式论证链**：内部写作检查清单按固定链路推进：D1：收入拆分 → 利润桥 → 资本消耗 → 现金质量 → 反证；D2：行业地图 → ROE 验证 → 护城河来源 → 伪优势过滤 → 同业对比 → 可持续 KPI；D3：周期属性 → 当前阶段 → 外部变量 → 财务敏感性 → 阈值；D4：治理红旗 → 管理层/控制权 → 资本配置 → 承诺兑现；D5：管理层核心叙事 → 财务验证 → 风险措辞变化 → 未解释清楚的问题 / 沉默信息；D6：触发条件表 → 是否展开 → 子公司/投资收益/SOTP 判断。
17. **公司赚钱公式**：D1 必须用一张 3-5 列窄表组织“收入来源 → 利润驱动 → 资本占用 → 现金转化 → 关键反证”，让读者一屏看懂这家公司如何赚钱、钱是否能留下、哪个变量会推翻判断；表前用“公司赚钱公式可以压缩为……”这类读者化结论句，不要用 bullet 替代表格。
18. **强周期单位经济模型**：若公司为强周期或周期属性明确，D1 必须输出单位经济模型，覆盖“销量 / 吨价 / 吨成本 / 吨毛利”，并说明量价成本如何传导到利润桥、现金质量和反证阈值；单位经济模型必须连接利润桥、现金质量、反证阈值和同业/区域坐标；没有吨口径时可用 ASP、单价、单位成本、单位毛利替代。
19. **护城河证伪表**：D2 必须用同一张 3-5 列窄表列出支持护城河的证据、削弱护城河的反证、同业/竞品验证、可持续 KPI；表前用“护城河证伪表的核心，是检验……”这类读者化结论句，主动检查伪优势，不要用 bullet 替代表格。
20. **护城河六步审讯链**：D2 必须用一张 3-5 列窄表把行业地图、量化验证、供给侧优势、需求侧弱点、规模边界、伪优势过滤、竞争对标和可持续 KPI 放在同一节里；先拆行业结构和优势来源，再用反证、同业和 KPI 判断护城河是否可持续。不得把高毛利、高 ROE、品牌知名度或市场份额直接当护城河；护城河来源必须拆成可验证机制，例如供给侧成本优势、需求侧粘性、转换成本、网络效应、渠道控制或客户认证；每个护城河来源必须同时给出反证信号和可持续 KPI；同业对比必须说明差异证明的是结构性优势还是阶段性结果；若优势只来自周期、价格、补贴、汇兑或一次性供需错配，应下调为半真优势或伪优势。
21. **竞争假说而非单向证明**：D2 两张护城河表后必须提出至少两种互相竞争、可证伪的优势解释，分别给出支持、反例、保留/否定结论和评级影响；同业既可作支持，也必须用于寻找现金转化、复购、研发效率或规模反例。
20. **治理链路**：D4 必须同时覆盖治理红旗、管理层/控制权、资本配置、承诺兑现；治理红旗先排雷，管理层/控制权看实控人、控股股东、核心管理层稳定性，资本配置看分红/回购/Capex/并购/投资回报，承诺兑现看管理层目标、经营计划或风险提示是否被财务结果验证。
21. **治理红旗排雷清单**：D4 必须用一张 3-5 列窄表覆盖审计意见、审计师变更、处罚、资金占用、关联交易、担保、质押、管理层稳定性，并写清异常阈值与重评动作；治理评价必须先排雷，再讨论资本配置加分项。
21. **管理层叙事审计表**：D5 必须用一张 3-5 列窄表按“管理层说法 → 财务验证 → 是否兑现 → 沉默信息 → 重评动作”组织；D5 必须同时覆盖历史指引、实际兑现、新战略、财务验证、风险措辞变化、沉默信息、重评动作，比较管理层叙事与收入、利润、现金流、资本开支和风险措辞变化是否一致，不要用 bullet 替代表格。
22. **MD&A 审讯表**：D5 必须用一张 3-5 列窄表按“管理层原始说法 → 财务验证 → 实际兑现 → 风险措辞变化 → 沉默信息 → 下一年复核指标”组织，逐条追问财务是否验证、是否兑现、哪些沉默信息会影响下一年重评。D5 不得复述 MD&A 原文后直接给管理层加分；必须把管理层叙事拆成可验证命题，逐项核对收入、毛利率、费用率、现金流、Capex、存货或应收的边际变化；管理层没有解释的边际变化必须列为沉默信息；风险措辞变化必须和实际财务变化交叉验证；若叙事与财务结果不一致，应明确下调管理层叙事可信度。
22. **外部变量敏感性表**：D3 必须输出周期/外部变量敏感性表，按“当前阶段 → 外部变量 → 财务敏感性 → 预警阈值 → 重评动作”组织，让读者知道外部变量如何改变收入、利润、现金流或评级；强周期公司必须明确 **需求周期 → 价格/成本 → ROE 修复空间 → 反证阈值** 的传导链，并说明只有需求周期、价格/成本和 ROE 修复空间同时改善，评级上修才有基础。D3 数据驱动周期链必须用 3-5 年数据验证需求、价格、成本、毛利率、ROE 和 FCF，并判断这些变量是否在同一时间轴上同步改善。强周期公司必须输出 D3 外部周期证据表，使用“变量类型 | 年度口径证据 | 来源 | 对财务传导的含义 | 缺口处理”组织，只补 2-3 个变量，优先覆盖需求 / 产量、价格趋势、主要成本变量；不得用零散月度新闻拼接长期序列，外部变量不能单独支撑评级上修，找不到年度或全年口径就写缺口。
23. **因果型周期分类**：不要机械二分强/弱周期。项目设备或定制交付公司应按客户资本开支 → 订单 → 制造交付 → 验收 → 收入 → 回款/现金写完整传导，并给出当前阶段；可用“订单周期敏感”等因果型参数值。
24. **项目营运资金桥**：D1 将固定资产投入、经营资产占用与经营负债融资分开；应收/存货增加是占用，应付/合同负债增加是融资，合同负债不得与资产相加称为占用。全部桥接科目必须取自同期间、同一张合并报表，不得混用母公司口径；票据必须在资产端与负债端对称检查。OCF 变化还要与销售收现、采购付现、职工、税费及其他经营收支等直接法现金流锚点复核，不能把精选资产负债表科目当成完整 OCF 恒等式。
25. **ROE 历史口径**：少于五个完整年度时，`roe_5y_avg` 写 null，并另写可得年度数与 `roe_available_years_avg`；不得把四年或三年均值命名为五年平均。
26. **SOTP 先审经济可分拆性**：模式判断必须检查客户、产品/技术、管理和共享资源、现金流、净债务、Capex、内部交易及资源分摊；数据缺失不是唯一理由，经济上无法独立也不能做 full。
23. **控股结构触发**：D6 必须覆盖触发条件、子公司、投资收益、SOTP 判断、阈值和计算依据，并使用小标题“### SOTP 触发决策表”。从 `not_applicable / diagnostic / listed_asset_bridge / full` 选择一种模式，逐项说明投资收益、母合差异、子公司利润、非经常性损益占比、海外资产回报、分部价值和控股折价是否触发；同时给出数据完备度、决策原因、最优可行分析、重复计价检查和升级条件。不得用“暂不展开完整 SOTP”代替分析。
24. **未来观察优先级**：未来观察变量必须按优先级分层，观察表必须包含“优先级”列，并至少使用 P0 / P1 / P2 三档区分立即重评变量、重点跟踪变量和低频复核变量。
25. **内部约束不得入正文**：不得把结构词、表格任务说明、渠道用途标签、模型指令写入正文；不要出现“这张表回答 / 下表回答 / 这张表的结论是 / 这张表的含义是 / 本表说明 / 表格用于 / 微信公众号摘要可复用一句话 / 可复用一句话 / 可作为微信公众号摘要”等模型视角或渠道复用标签。表前必须写读者化结论句，表后必须写投资含义；可用“关键结论是”“这组证据说明”“投资含义：”，不要用“这张表说明”，也不要写成“投资含义是：”。
26. **异常优先**：每个维度都要主动寻找异常、矛盾、不符合直觉或管理层没有解释清楚的地方；不要只写支持结论的顺证。
27. **D4 资本配置复盘表**：D4 必须输出资本配置复盘表，按“动作 → 金额 → 管理层理由 → 后续结果 → 质量评价”组织，复盘分红、回购、Capex、并购、投资或处置等动作，不能只写当年事实。
28. **D5 历史目标 vs 实际兑现表**：D5 必须输出历史目标 vs 实际兑现表，按“年份 → 管理层目标 → 实际结果 → 偏差 → 投资含义”组织，量化历史指引、实际兑现、新战略和未解释事项。D5 必须同时出现“历史指引”“实际兑现”“新战略”“财务验证”“风险措辞变化”“沉默信息”，不要用近义词替代这些关键契约词。
29. **近五年质量趋势**：强周期、重资产或资本强度较高的公司必须输出“近五年质量趋势”，用图表友好的窄表覆盖“ROE / 毛利率 / 净利率 / FCF / Capex/D&A”等趋势证据，说明商业质量是周期高点、低谷修复还是长期稳定。
30. **图表友好表格**：业务拆分、吨经济模型、区域毛利率、五年趋势等关键数据必须拆列成可画图表格；业务名称和金额必须拆成两列，不得写成“42.5级水泥约486亿元”这类产品名+金额合并单元格。强周期/重资产公司优先使用 `业务 | 收入 | 收入占比 | 毛利率 | 同比`、`年份 | ROE | 毛利率 | 净利率 | FCF | Capex/D&A`、吨经济模型、区域毛利率等图表友好表格。
31. **chart_ready 图表元信息契约**：每个核心图表模块必须按“标题 → 图表元信息 → 读图结论 → 纯数值表 → 投资含义”组织；标题后紧跟一行 `chart_ready: true; chart_type: line|bar|mixed; x_axis: 年份/业务/公司/区域; bar_series: 收入/利润/Capex; line_series: 毛利率/ROE/Capex/D&A; unit_map: 收入=亿元, 毛利率=%`。图表元信息不得替代正文判断，只服务 HTML 渲染器识别；chart_type 只能使用 line、bar、mixed。纯数值表只允许维度列、年份列和干净数值列，解释、证据、判断、含义、来源、口径说明必须放在表前表后，不能混入图表数据列。
31. **图表形式逻辑**：图表形式必须服务因果链，每张图表友好表格前必须写读图结论；金额指标优先用柱状图，比率 / 毛利率 / ROE / Capex/D&A 优先用折线图；趋势数据优先覆盖 3-5 年；收入、利润、ROE、现金、资本消耗、单位经济等指标应按同一因果链组合，不得硬套样板公司的图表组合。
32. **图表问题驱动**：每张图回答一个投资问题，图表标题必须是问题型或结论型，图表指标必须在同一因果链上，不得为了凑图表堆数据。强周期或重资产公司优先回答：ROE 是否穿越周期、现金流是否覆盖资本开支、毛利改善来自价格还是成本、同业对比证明的是成本优势还是只证明规模大。
33. **投资问题驱动证据表**：证据表必须回答一个明确投资问题，并按“投资问题 → 读图结论 → 表格证据 → 投资含义”组织；每组数据必须先说明它在验证哪个判断，表后必须写清楚该组证据如何影响评级、风险或反证阈值；不得只列数据不解释含义，不得把解释性字段混入图表友好数据列；图表友好数据列只放干净数值，读法、解释、证据、影响、判断、含义必须移到表前表后文字或非图表表格，不得把金额和证据写在同一个单元格。
33. **图表密度与标题**：强周期或重资产公司至少 5 个可渲染 chart_ready 图表、至少 4 组图表友好证据模块，必须覆盖五类图表原型：业务或区域结构、资本消耗（Capex/D&A 或资本开支 vs 折旧摊销）、现金转化（OCF/净利润、营运资本或应收账款）、盈利能力趋势（ROE / 毛利率 / 净利率）以及同业或效率对比；图表标题必须是结论型标题，标题不能只写模块名，不得用“读图结论：”作为标题前缀，“读图结论”只放在标题后的正文句子里。核心图表必须优先拆成 5-6 张样板式小图，覆盖收入利润趋势、业务或区域收入结构、资本支出 vs 折旧摊销与 Capex/D&A、现金转化或 OCF/净利润与应收、ROE 趋势、同业规模或效率对比；不得把需求、价格、成本、毛利率、ROE、FCF 全部塞进同一张图。收入利润ROE因果链不能命名为“收入利润ROE因果链”，单位经济模型不能命名为“单位经济模型”，资本配置复盘表不能命名为“资本配置复盘表”。
34. **HTML 渲染契约**：核心图表标题必须显式使用图表一、图表二、图表三、图表四、图表五、图表六，方便网页渲染器把图表一放在 Executive Summary 后，把图表二、图表三、图表四放在 D1 内，把图表六放在 D2 内，把图表五放在 D3 内；该编号只定义网页阅读位置，不要求机械复制任何样板公司的数据或图表组合。
33. **利润桥 / 同业 / 控股网络深度**：强周期或重资产公司的利润桥细项必须拆到毛利 / 费用 / 减值 / 投资收益 / 非经营项等多个具体驱动，费用端至少拆出两个具体费用项，例如销售费用 / 管理费用 / 研发费用 / 财务费用；利润桥必须按 **报表利润 → 核心经营利润 → 可持续利润** 重算，输出核心经营利润重算，剔除非经常性损益、投资收益和一次性因素，并判断可持续利润是否支撑当前评级；计算依据必须能从表格数字复核；利润桥重算必须写出计算依据或计算口径；必须出现支撑当前评级或评级仍成立；D2 必须写具名同业，D2 的具名同业对比必须放在维度二正文内，同业表第一列必须直接写公司名称，若可比数据不可得必须说明缺口和复核动作，同业坐标表必须包含比较维度；D6 必须穿透控股股东 / 子公司 / 关联平台 / 相关上市平台，并说明是否改变投资收益、SOTP 或控股折价判断。
34. **validator 精确契约**：D2 护城河证伪表必须逐字包含支持护城河、削弱护城河、同业/竞品验证、可持续 KPI；D3 数据驱动周期链同一张表必须逐字覆盖需求、价格、成本、毛利率、ROE、FCF；公司类型化证据模块必须同时出现产业坐标、区域/客户结构、同业/区域坐标、单位经济模型、利润桥、现金质量、反证阈值；样板证据模块必须逐字出现收入质量拆分、利润桥、量价成本拆解、现金转化、治理红旗、MD&A 叙事 vs 财务证据、伪优势过滤。
30. **D4/D5 多年复盘**：D4/D5 必须写多年复盘状态和多年兑现状态，资本配置后续结果和历史目标兑现至少覆盖多期变化，不能只写当年事实。
29. **报告局限与数据警示**：正式报告必须使用独立二级标题“## 报告局限与数据警示”，说明数据口径冲突、同业数据缺口、披露不足事项及后续复核动作；必须逐字覆盖：数据口径冲突、同业数据缺口、披露不足、后续复核；这不是免责套话，而是研究置信度说明。报告局限与数据警示作为附录材料处理，不得压过 Business Quality Verdict、Executive Summary、D1-D6、交叉验证、深度总结和未来观察变量。
30. **附录和框架说明降权**：报告局限、数据警示、结构化参数、分析框架与评级标准只能作为附录材料；不得在 Executive Summary、D1-D6 或深度总结中解释框架定义；不得把 Greenwald、护城河框架、评级标准写成主线段落；正文只写公司判断、证据和投资含义；附录内容不得压过 Business Quality Verdict、Executive Summary、D1-D6、交叉验证、深度总结和未来观察变量；结构化参数只用于机器读取和 HTML 折叠面板；分析框架说明只用于读者需要时展开阅读。
30. **公开输出清洁**：正文和数据来源不得出现本地绝对路径，不得出现 WebSearch fallback，不得出现 acceptance samples，也不得出现 e2e、fixture、validator 等内部链路痕迹；公开报告只描述数据类别、来源口径和置信度。
31. **微信窄表化**：每个维度至少一张 3-5 列窄表，表前用读者化结论句交代判断背景，表后用一句话说明投资含义。

## 微信公众号 / 网页可读性要求

13. **首屏摘要卡**：Business Quality Verdict 后必须提供窄版首屏摘要卡，固定使用 `| 项目 | 结论 |` 表头，回答公司本质、商业质量、护城河来源、最大风险、周期位置（如适用）、反证条件；不要用“问题 / 回答”或“判断项 / 结论 / 核心依据”替代表头。
14. **核心发现**：Executive Summary 后必须提供“五个核心发现”（或同名核心发现小节），用 5 条短 bullet 提炼最影响商业质量判断的事实、含义和风险，避免只写一段摘要。
15. **章节小结**：D1-D6 每个大维度必须使用二级标题“## 维度一：...”“## 维度二：...”到“## 维度六：...”，不得只写“## D1.”；每章必须用“本章小结”收尾，包含本章结论：、最重要证据：、观察风险 / 重评触发：。
16. **短段落**：正文段落尽量控制在 4-6 行 Markdown 源文本以内，正文单行尽量控制在 100 个中文字符以内；超长论证拆成短段或编号列表。
17. **窄表格**：优先使用 3-5 列表格；若数据很多，只保留最能支撑判断的列，且每张表前后必须有一句说明它支持什么判断。
17A. **维度状态**：每个维度开头必须给出读者可见的本章评级、维度评级、综合评价或风险状态，状态词优先使用正面 / 中性 / 负面 / 风险观察 / 反证触发，方便网页渲染器生成标题 badge 和正文状态标签。
18. **图表写法**：若报告后续会进入微信公众号，所有趋势图都必须有结论型标题和“读图结论”；不要只写“收入利润趋势”这类中性标题。
19. **关键数字突出**：关键评级、阈值、异常值和风险触发条件用粗体突出。
20. **避免审计式堆叠**：不要连续罗列大量数据而不解释含义；每组数据必须服务一个判断。
21. **摘要可复用**：Executive Summary 中至少有一句短摘要可作为微信公众号 digest 的基础。
22. **参数附录化**：结构化参数必须保留，但应标为“结构化参数（机器读取 / 附录）”，避免压过人工阅读结论；必须显式包含 shared/report_contract.json 列出的全部机器字段。总体商业质量评级、展望、护城河评级和 SOTP 模式必须分列。
23. **文章式结尾**：深度总结按“公司本质 → 为什么优势真实 → 最大风险 → 重评触发”组织，不要只堆维度摘要。
